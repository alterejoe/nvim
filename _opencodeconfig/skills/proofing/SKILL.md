# Proofing Requirements System

## Problem

Proofing records are created and resolved across two servers (admin + client) with no shared contract. Each handler independently decides what records to create, when to resolve them, and how to interpret status. The admin progress tree compensates with silent auto-derivation hacks instead of reflecting the actual database state.

**Consistency failures:**
- Admin adds a contest → `contest_meta:unresolved` → tree shows unresolved → client completes ordering → `choice_order:reviewed` → but `contest_meta` stays `unresolved` because no shared contract says "contest requires 3 proofing types"
- Admin tree auto-derives "reviewed" for contests with non-imported choices, but misses zero-candidate edge case
- Adding a new entity type requires duplicating proofing creation logic across handlers
- No single source of truth for "what does a fully-proofed contest look like?"

## Solution

A Go package at `portal-shared/proofing/` with four layers, all in one module:

```
shared/proofing/
├── requirements.go   # what records each entity type requires
├── status.go         # OverallStatus(), Missing(), status constants
├── actions.go        # named state transitions (what changes per action)
├── queries/          # wrapper functions over the generated sqlc code
│   └── proofing.go
├── sqlc/
│   └── queries.sql   # raw SQL queries for sqlc generation
├── db/               # generated Go code from sqlc (committed, regenerated)
│   ├── db.go
│   ├── models.go
│   └── queries.sql.go
├── sqlc.yaml         # sqlc config
├── schema.sql        # pg_dump output — regenerated by `make sqlc`
└── Makefile          # `make sqlc` = pg_dump + sqlc generate
```

**Key rule:** the `proofing` package (requirements, status, actions) is pure Go — no database access. Only the `queries/` wrapper and `db/` generated code talk to the database.

## Package Files

### `requirements.go` — entity requirements table

Maps entity types to the record types they require. Single source of truth.

```go
package proofing

type RecordRequirement struct {
    RecordType string // "contest_meta", "choice_order", "pp_state_code", etc.
    Label      string // Human label for progress tree
}

type EntityRequirements struct {
    EntityType string              // tree node: "contest", "polling_place", etc.
    Records    []RecordRequirement
}

// Current entity types:
//   contest       → contest_meta, contest_state_code, choice_order
//   polling_place → pp_meta, pp_state_code
//   state_code    → state_code
//   choice        → choice_meta

func ForEntityType(entityType string) *EntityRequirements { ... }
```

### `status.go` — overall status computation

```go
package proofing

type StatusMap map[string]string // record_type → status

const (
    StatusReviewed      = "reviewed"
    StatusNeedsRevision = "needs_revision"
    StatusUnresolved    = "unresolved"
)

// OverallStatus returns "reviewed", "needs_revision", "unresolved", or "".
func OverallStatus(entityType string, records StatusMap) string { ... }

// Missing returns record types not yet reviewed.
func Missing(entityType string, records StatusMap) []RecordRequirement { ... }
```

Priority: `needs_revision` > `unresolved` > `reviewed`.

### `actions.go` — named state transitions

Maps actions to the set of `RecordSpec` results they produce. Each handler calls the action function and upserts the returned specs.

```go
package proofing

type RecordSpec struct {
    EntityType string // record type ("choice_order", "contest_meta", etc.)
    Status     string // StatusReviewed, StatusUnresolved, etc.
    Source     string // optional context; empty = omit at call site
}

func ActionAccepted()          []RecordSpec  // filing paper accepted
func ActionIgnored()           []RecordSpec  // filing paper ignored
func ActionOrderingSaved()     []RecordSpec  // ordering saved (has candidates)
func ActionOrderingSavedEmpty() []RecordSpec // ordering saved (no candidates)
func ActionReconcileSaved()    []RecordSpec  // reconciliation saved
func ActionCandidateMapped()   []RecordSpec  // candidate mapped by admin
```

### `sqlc/` + `db/` — generated database layer

`schema.sql` is a pg_dump of the `clerk` schema (full, not just proofing tables) — required by sqlc for type generation of UUID, enum, etc.

`sqlc/queries.sql` contains four queries:

| Query | Purpose |
|-------|---------|
| `UpsertProofingRecord` | INSERT … ON CONFLICT DO UPDATE, returns ID |
| `GetProofingRecord` | Single record by (election_id, entity_type, entity_id) |
| `GetProofingRecordsByElectionAndType` | All records for an election + type |
| `GetLatestProofingRecordsByElectionAndType` | Latest per entity_id (DISTINCT ON) |

Run `make sqlc` to regenerate:

1. Dumps `clerk` schema via pg_dump → strips `\restrict`/`\unrestrict` lines (pg_dump 17 garbage) → writes `schema.sql`
2. Runs `sqlc generate` → writes to `db/`

**Important:** pg_dump v17 injects `\restrict` / `\unrestrict` meta-commands. The Makefile filters them with `grep -v '^[\]'`. If you upgrade pg_dump and get a `syntax error at or near "\"`, check for new backslash commands and update the grep.

### `queries/proofing.go` — wrapper functions

Thin wrappers over the generated sqlc functions. Standardizes error wrapping with `fmt.Errorf("QueryName: %w", err)`.

```go
package queries

import (
    "github.com/Glass6444/portal-shared/proofing/db"
    "github.com/jackc/pgx/v5/pgtype"
)

func UpsertProofingRecord(ctx context.Context, arg db.UpsertProofingRecordParams, q *db.Queries) (pgtype.UUID, error)
func GetProofingRecord(ctx context.Context, arg db.GetProofingRecordParams, q *db.Queries) (db.ClerkProofingRecord, error)
func GetProofingRecordsByElectionAndType(ctx context.Context, arg db.GetProofingRecordsByElectionAndTypeParams, q *db.Queries) ([]db.ClerkProofingRecord, error)
func GetLatestProofingRecordsByElectionAndType(ctx context.Context, arg db.GetLatestProofingRecordsByElectionAndTypeParams, q *db.Queries) ([]db.ClerkProofingRecord, error)
```

## Handler Integration Patterns

### Pattern A: Creating an Entity

When adding a new entity (contest, polling place, state code), create ALL required records as `unresolved` in one loop inside the TX.

```go
import (
    "github.com/Glass6444/portal-shared/proofing"
    proofingdb "github.com/Glass6444/portal-shared/proofing/db"
    proofingqueries "github.com/Glass6444/portal-shared/proofing/queries"
)

// Inside WithTx block:
pq := proofingdb.New(tx)

for _, req := range proofing.ContestRequirements.Records {
    proofingqueries.UpsertProofingRecord(ctx, proofingdb.UpsertProofingRecordParams{
        ElectionID:  pgElectionID,
        EntityType:  req.RecordType,
        EntityID:    pgEntityID,
        Status:      proofing.StatusUnresolved,
        SubmittedBy: pgUserID,
    }, pq)
}
```

**Rules:**
- Always use `proofing.StatusUnresolved` at creation time
- Always iterate `ForEntityType(type).Records` — never hardcode records
- New entity types: add to `AllRequirements` first, then follow this pattern

### Pattern B: Resolving via Action

When an action completes, use the action's `RecordSpec` list. This is the standard way both servers resolve records.

```go
// Inside WithTx after the work is done:
pq := proofingdb.New(tx)

for _, spec := range proofing.ActionOrderingSaved() {
    proofingqueries.UpsertProofingRecord(ctx, proofingdb.UpsertProofingRecordParams{
        ElectionID:  pgElectionID,
        EntityType:  spec.EntityType,
        EntityID:    pgContestID,
        Status:      spec.Status,
        Source:      pgtype.Text{String: spec.Source, Valid: spec.Source != ""},
        SubmittedBy: pgUserID,
    }, pq)
}
```

**Rules:**
- Call the action function — never assemble `RecordSpec` manually
- Each action resolves exactly the records it owns
- `Source` is optional; set `Valid: false` to omit

### Pattern C: Progress Tree Rendering

Collect records per entity into a `StatusMap`, then call `proofing.OverallStatus()`.

```go
import "github.com/Glass6444/portal-shared/proofing"

func computeContestStatus(contest *ProofingTreeNode) string {
    records := proofing.StatusMap{}
    records["contest_meta"] = contest.Status
    for _, child := range contest.Children {
        if child.EntityType == "contest_state_code" {
            records["contest_state_code"] = child.Status
        }
        if child.EntityType == "choice_order" {
            records["choice_order"] = child.Status
        }
    }
    return proofing.OverallStatus("contest", records)
}
```

**Rules:**
- Tree MUST reflect database — no auto-derivation, no silent status changes
- If a contest shows "unresolved", there is an actual unresolved record
- `OverallStatus()` is the single source of truth for rendering

## Adding a New Entity Type

1. Add to `AllRequirements` in `requirements.go`
2. If the entity has action-based resolution, add an `Action*()` function in `actions.go`
3. Admin create handler: loop over `ForEntityType(newType).Records` inserting `StatusUnresolved`
4. Tree rendering: `OverallStatus(newType, statusMap)` just works
5. Client resolution: call the action function inside the handler TX
6. Run `make sqlc` only if the schema changed (new proofing table or column)
7. Both servers: `go build ./...`

No duplicated logic. No schema changes for new entity types.

## Common Pitfalls

- **Creating records outside the requirements loop** — always iterate `ForEntityType(type).Records`. Hardcoded `UpsertProofingRecord(ctx, ..., EntityType: "contest_meta")` defeats the shared contract.
- **Resolving without an action function** — always use `proofing.Action*()` to get `RecordSpec` list. Don't hand-assemble specs.
- **Forgetting to add new requirements to `AllRequirements`** — new entity type → add to the table first. The tree won't show it without a definition.
- **Mixing creation and resolution in the same handler** — creation = `StatusUnresolved` at entity creation. Resolution = `StatusReviewed` when an action completes. Don't upsert `reviewed` at creation time.
- **Auto-deriving in the tree** — tree must reflect DB. If status looks wrong, fix the handler that creates/resolves records, not the tree rendering.
- **StatusMap keys must match RecordType exactly** — `"contest_meta"` not `"contest"`. Mismatch = never recognized as complete.
- **`make sqlc` fails with `\` syntax error** — pg_dump v17+ injects backslash meta-commands. The Makefile grep handles `\restrict`/`\unrestrict`. If new backslash commands appear, update the grep.
- **Not regenerating `schema.sql` after schema changes** — the `schema.sql` is a pg_dump output. If the proofing_records table changes, run `make sqlc` to keep the generated types in sync.

---

**Key insight:** The `proofing` package never touches the database. It's pure structs + functions. Servers import the package, use `queries/` wrappers against generated `db/` code to persist records, and call `OverallStatus()` / action functions for consistent behavior. The requirements table is the contract that keeps both servers synchronized.
